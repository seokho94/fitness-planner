### 1.3 기록 유형별로 보여 주는 지표

통계는 운동의 `trackingType`(T1 4장)에 따라 다른 지표를 쓴다. **볼륨과 1RM은 `WEIGHT_REPS`에만 있다.**

| --- | --- | --- | --- | --- | --- |
| `WEIGHT_REPS` | 집계 | 집계 (`weight>0`, `reps≤12`) | 추정 1RM | 볼륨 | `reps` 합산 |

## 2. 계산 적용 규칙

### 2.1 공통

- 모든 값은 저장하지 않고 화면을 열 때 WorkoutSet에서 계산한다(T1 5장). 화면은 `useLiveQuery`로 구독하므로 세션 종료·수정·삭제·가져오기 후 자동으로 다시 계산된다.
- 계산은 순수 함수로 `src/domain/stats/`에 모으고, 화면은 결과만 그린다. Vitest 단위 테스트는 2.6절 계산 예시를 그대로 테스트 케이스로 쓴다.
- 계산 중에는 반올림하지 않고, 표시할 때만 IA 5.1절 형식으로 반올림한다(볼륨 정수, 1RM 소수 첫째 자리).

```ts
// src/domain/stats (초안 시그니처)
isCountableSet(set: WorkoutSet, session: WorkoutSession): boolean;      // 1.2절 집계 대상 세트
setVolume(set: WorkoutSet, ex: Exercise): number | null;                 // WEIGHT_REPS만 weight*reps, 그 외 null
estimate1RM(set: WorkoutSet, ex: Exercise): number | null;               // 2.3절. 대상 아니면 null
sessionLocalDate(session: WorkoutSession): LocalDate;                    // startedAt → 로컬 YYYY-MM-DD
weekStartOf(date: Date): LocalDate;                                      // startOfWeek(date, { weekStartsOn: 1 })
resolveRange(range: StatsRange, today: Date, firstSessionAt?: Date): { start: Date; endExclusive: Date; bucket: 'week' | 'month' };
```

### 2.2 볼륨 (F-ST-04)

| 범위 | 계산 | 표시 위치 |
| --- | --- | --- |
| 세션 볼륨 | 그 세션의 `WEIGHT_REPS` 집계 대상 세트 `weight × reps` 합 | S-11 세션 항목, S-12, S-10 |
| 주간·월간 볼륨 | 버킷 기간에 세션 날짜가 속한 세션들의 세션 볼륨 합 | S-11 주 머리글, S-13 기간 볼륨 차트 |
| 운동별 볼륨 | 한 운동의 집계 대상 세트 `weight × reps` 합(세션별 또는 기간 합) | S-03 볼륨 차트, S-13 운동별 볼륨 목록 |

- `REPS_ONLY`, `DURATION` 세트는 볼륨에 넣지 않는다. 세트 수에는 들어간다.
- `reps > 12` 세트도 볼륨에는 **넣는다**. 12회 제한은 1RM에만 적용한다.
- `weight = 0` 세트는 볼륨 0을 더한다(세트 수에는 들어감).
- 볼륨이 계산되는 세트가 하나도 없는 세션의 볼륨은 0이 아니라 **값 없음(`–`)** 으로 표시한다. 주·월 버킷은 세션이 없거나 `WEIGHT_REPS` 세트가 없으면 0으로 그린다(차트 축을 유지하기 위해).

### 2.3 추정 1RM (F-ST-05)

- 대상: `WEIGHT_REPS` 집계 대상 세트 중 `weight > 0` 이고 `1 ≤ reps ≤ 12`(Q-2 확정).
- 세트 1RM: `reps = 1`이면 `weight`, 아니면 `weight × (1 + reps / 30)` (Epley, T1 5.2절).
- **세션 1RM** = 그 세션에서 그 운동의 세트 1RM 최댓값. 대상 세트가 없는 세션은 값이 없고 차트에 점을 찍지 않는다(0으로 찍지 않음).
- 최댓값이 같은 세트가 여럿이면 툴팁의 "근거 세트"는 `setOrder`가 가장 작은 세트로 한다.
- 기간 최고 = 기간 안 세션 1RM의 최댓값.

### 2.4 `REPS_ONLY`·`DURATION` 운동의 추이 (F-ST-03)

| 지표 | 세션 값 | 값이 없는 경우 |
| --- | --- | --- |
| 최고 횟수 | 그 세션·그 운동 집계 대상 세트의 `reps` 최댓값 | 집계 대상 세트가 없으면 점 없음 |
| 총 횟수 | 같은 세트들의 `reps` 합 | 0 |
| 최장 시간 | 같은 세트들의 `durationSec` 최댓값 | 점 없음 |
| 총 시간 | 같은 세트들의 `durationSec` 합 | 0 |

- 이 운동들은 S-03에 볼륨·1RM 탭이 없고, S-13의 1RM 운동 선택 목록에도 나오지 않는다.

### 2.5 기간 경계와 시간대

- 기간·버킷 경계는 **기기의 현재 로컬 시간대**로 계산한다. date-fns `startOfWeek(d, { weekStartsOn: 1 })`, `startOfMonth`, `addWeeks`, `addMonths`를 쓰고 밀리초 더하기(`+ 7 * 86400000`)는 쓰지 않는다(서머타임이 있는 시간대에서 경계가 어긋남).
- DB 조회는 로컬 경계를 `Date`로 만든 뒤 `toISOString()`으로 바꿔 `workoutSessions.startedAt` 인덱스 범위(`between(startIso, endIso, true, false)`)로 읽는다.
- 세션은 시작 시각 하나로만 기간에 속한다. 일요일 23:40에 시작해 월요일 00:50에 끝난 세션은 **일요일이 속한 주**에 들어간다.
- 기기 시간대가 바뀌면(해외 여행 등) 다음 계산부터 새 시간대로 다시 나눈다. 저장 값(`startedAt` UTC)은 바뀌지 않는다.
- "오늘"·"이번 주"는 화면을 열 때와 앱이 포그라운드로 돌아올 때 다시 계산한다(자정을 넘겨 켜 둔 경우 대비).

### 2.6 계산 예시 (공통 데이터)

기기 시간대 `Asia/Seoul`(UTC+9), 오늘 **2026-10-01(목)**. 이번 주는 9월 28일(월) ~ 10월 4일(일)이다.

| 세션 | 로컬 시작 ~ 종료 | `startedAt` (UTC) | 상태 | 세션 날짜·주 |
| --- | --- | --- | --- | --- |
| P 상체 B | 9/27(일) 22:00 ~ 22:55 | `2026-09-27T13:00:00Z` | COMPLETED | 9/27, **지난주**(9/21~9/27) |
| A 상체 A | 9/28(월) 19:30 ~ 20:32 | `2026-09-28T10:30:00Z` | COMPLETED | 9/28, 이번 주 |
| B 하체 A | 9/30(수) 23:40 ~ 10/1(목) 00:50 | `2026-09-30T14:40:00Z` | COMPLETED | **9/30**, 이번 주 |
| C 상체 A | 10/1(목) 18:00 ~ (진행 중) | `2026-10-01T09:00:00Z` | IN_PROGRESS | 집계 제외 |

### 2.7 워밍업 세트

- 세트 유형 표시(F-WS-05)는 C라 MVP UI로는 `WARMUP` 세트를 만들 수 없다. 하지만 JSON 가져오기로 들어올 수 있으므로 계산은 T1 5장대로 `WARMUP`을 제외한다.
- S-03 기록 목록에서는 `WARMUP` 세트를 `W` 번호로 보여 주고 지표 칸에 `집계 제외`라고 쓴다.

## 3. 공통 화면 규칙

### 3.1 기간 필터 (S-13, S-03 공통)

`FilterChipGroup`(`type='single'`, IA 3.6절)로 고른다. 값은 URL `?range=`에 둔다(IA 2.5절). 잘못된 값이면 기본값 `12w`로 바꾼다(`replace`).

| 값 | 라벨 | 시작 | 끝(미포함) | 버킷 | 오늘이 2026-10-01일 때 |
| --- | --- | --- | --- | --- | --- |

- 이번 주(이번 달) 버킷은 아직 오지 않은 날을 포함하지만 그대로 한 버킷으로 그린다.
- S-13에서 S-03으로 이동할 때 현재 `range`를 그대로 넘긴다(`/exercises/:id?range=12w`).

### 3.2 빈 상태 원칙

| 상황 | 표시 |
| --- | --- |
| 화면 전체에 보여 줄 기록이 없음 | 화면 본문 자리에 `EmptyState(variant='empty')` 하나. 기간 필터 등 조작 요소는 숨긴다 |
| 기록은 있지만 선택한 기간·카드에 데이터가 없음 | 해당 카드 안에 작은 `EmptyState`(아이콘 생략, 제목 + 설명 + 선택 버튼). 다른 카드와 필터는 그대로 |

| 불러오는 중 | 차트·목록 자리에 같은 높이의 스켈레톤(shadcn `Skeleton`). 200ms 안에 끝나면 보여 주지 않는다 |

#### 4.1.3 데이터 읽기

1. `workoutSessions.orderBy('startedAt').reverse()`에서 `status='COMPLETED' && deletedAt=null`만 거른다.
2. **주 단위로 끊어 읽는다.** 세션을 30개 이상 읽을 때까지 읽되, 마지막 세션이 속한 주의 세션은 끝까지 읽는다. 주 머리글의 세션 수·볼륨이 페이지 경계에서 잘리지 않게 하기 위해서다.
3. 읽은 세션의 세트는 `workoutSets.where('sessionId').anyOf(ids)`로 한 번에 읽어 세션별로 계산한다.
4. 세션 수정·삭제(S-12), 가져오기(S-16) 후에는 `useLiveQuery`가 다시 계산한다. 이미 불러온 묶음 수는 유지한다.

## 5. S 기능 요약

### 5.1 F-ST-02 캘린더 보기 (S-11 캘린더)

- 경로: `/history?view=calendar&month=2026-09` (`month` 없으면 이번 달)
- 규칙
  - 월 달력, 월요일 시작(`월 화 수 목 금 토 일`). 앞뒤 달 날짜 칸은 비워 둔다.
  - 집계 대상 세션이 있는 날(세션 날짜, 2.5절)에 표시를 단다. 같은 날 2개 이상이면 숫자 배지(`2`).
  - 오늘은 테두리로 강조. 미래 날짜는 흐리게, 누를 수 없음.
  - 날짜를 누르면 세션 1개면 S-12로 이동, 2개 이상이면 그날 세션 목록 `BottomSheet`(4.1.1절 항목과 같은 모양)를 연다. 세션 없는 날은 반응 없음.
  - `[<]`·`[>]`로 달 이동(`?month=`를 `replace`). 이번 달보다 뒤로는 갈 수 없고(`[>]` 비활성), 앞으로는 첫 세션이 있는 달까지.
  - 달력 아래에 그 달 요약: `9월  운동 11회  볼륨 28,400 kg`.

```text

|   o         o                        |

|   o         o                   o    |
```

| 2 | 운동한 날 표시 | `o` 자리에 실제로는 채운 원 + `aria-label="9월 28일, 운동 1회"`. 색만으로 구분하지 않는다 |

### 5.2 F-ST-06 부위별 빈도 (S-13 부위별 세트 수, Q-1 반영)

- 계산: T1 5.3절. **Q-1 확정: 주 부위(`primaryMuscle`)만 집계 대상 세트 1개당 1세트로 센다. 보조 부위는 반영하지 않는다.**
- 횟수: `WEIGHT_REPS`·`REPS_ONLY` 세트의 `reps` 합. `DURATION`은 세트 수만 센다.
- 표시: S-13 `부위별 세트 수` 카드(4.3.1절 #4). 기간 필터(3.1절) 전체 기간 합계를 세트 수 내림차순으로 가로 막대(7장 C-2). 같으면 `MuscleGroup` 정의 순(T1 1.4절). 세트 0인 부위는 기본적으로 숨기고 `[ 모든 부위 보기 ]`로 13개 부위를 모두 펼친다(0세트 부위가 소홀한 부위를 찾는 데 쓰이므로).
- 막대 툴팁·표: `가슴 3세트 · 33회`, `복근 2세트`(횟수 없음).
- 예시(2.6절 이번 주): 가슴 3세트·33회, 대퇴사두 3세트·22회, 등 2세트·18회, 복근 2세트. 벤치프레스의 보조 부위 삼두·어깨, 스쿼트의 보조 부위 둔근·햄스트링·복근은 더하지 않는다.
- 빈 상태: 기간에 집계 대상 세트가 없으면 카드 안 "이 기간에는 운동 기록이 없어요". `REPS_ONLY`·`DURATION`만 있어도 세트 수는 있으므로 정상 표시한다.
- 인수 조건 요약: Given 이번 주 벤치프레스(주 CHEST, 보조 TRICEPS·SHOULDERS) 4세트 × 8회 / When S-13 range=4w의 부위별 카드를 본다 / Then 가슴 4세트·32회가 보이고 삼두·어깨에는 이 세트가 더해지지 않는다.

### 7.5 빈 데이터·특수 데이터 처리

| 상황 | 처리 |
| --- | --- |
| 데이터 배열이 비어 있음 | **차트를 렌더링하지 않고** 카드 안 `EmptyState`(6장)를 그린다. 빈 축만 있는 차트는 보이지 않는다 |
| 막대 차트의 모든 값이 0 | 빈 데이터와 같게 처리(6장 해당 문구) |
| 막대 차트의 일부 버킷이 0 | 버킷을 빼지 않고 0으로 넣는다(축 간격 유지). 툴팁은 `볼륨 0 kg`, `세션 0회` |
| 선 차트의 값이 없는 세션 | 데이터에 넣지 않는다(0이나 `null`로 넣지 않음). 따라서 `connectNulls`는 쓰지 않는다 |
| 선 차트 점 1개 | `Line dot`를 항상 표시하고 3.2절 안내 문구 |
| 선 차트 점이 30개 초과 | 평소 점은 숨기고(`dot={false}`) 활성 점만 표시(`activeDot`) |
| 버킷이 많음(`all` 월 버킷 수십 개) | 막대 폭은 Recharts 자동, 눈금은 `minTickGap`으로 솎는다. 가로 스크롤은 쓰지 않는다 |
| 같은 시각의 세션 2개(가져오기 데이터) | 둘 다 점을 찍는다. 툴팁은 마지막 활성 점 기준 |
